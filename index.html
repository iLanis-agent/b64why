B64Why
Your base64 decodes fine in one language and fails in another. Here is why.
Open the app
Zm9vYg is "foob" with the padding cut off. A strict decoder rejects it, Node accepts it. -_8 is URL-safe base64 and fails the standard decoder.

What it does

  • Decodes with a strict RFC 4648 decoder (standard and URL-safe) and a lenient Node-style one, side by side.
  • Names the exact problem: wrong alphabet, bad padding, junk characters, impossible length.
  • Encodes text three ways and shows the size overhead.
  • Runs in your browser. Nothing is uploaded.

How far to trust it

  • Passes the RFC 4648 test vectors, 4000 random encodings against Python, 6000 mutated strings against Python strict decoding, and 6000 against Node lenient decoding.
  • One known difference: Python accepts surplus padding, this strict decoder does not.
